# KiCad schematics

Real KiCad 7 schematics, not images. `gan_buck.kicad_sch` opens in eeschema
and is editable.

## Why it is generated, not drawn

Component values in this project move. `RDEC` went from 20 mΩ to 1 Ω after
the 200 V shoot-through investigation, and a sheet drawn by hand in a GUI
would still be showing 20 mΩ. `scripts/kicad_schematic.py` reads the values
out of `sim/buck.cir` at build time, so the schematic and the circuit that
was actually simulated cannot disagree.

Regenerate after any netlist change:

```
python3 scripts/kicad_schematic.py
```

## Two things a reader should know

**The GaN symbol.** KiCad 7 ships no GaN HEMT symbol. `Q_NMOS_DGS` is used
and labelled "eGaN HEMT", which is what EPC's own application schematics do.
The device has **no body diode** — reverse conduction during dead time costs
Vth + |Voff| + I·Rds(on) rather than one diode drop, and that sets the
dead-time trade. The sheet says so, because a reader who takes the MOSFET
symbol literally will mis-read the dead-time behaviour.

**The 0 V sources are not drawn.** `buck.cir` carries `Vsin`, `Vshs`, `Vsls`
and `Vsout` purely so ngspice can measure current through them. They are
measurement points, not components, and drawing them would imply hardware
that does not exist. A note on the sheet says where they are.

## Rendering the PNG

`kicad-cli` exports SVG and PDF. The PNG preview is rasterised separately
with PyMuPDF (`pip install pymupdf`); it is a convenience, not part of the
toolchain.

## The driver sheet

`gan_segdrv.kicad_sch` draws `models/segdrv.lib` element by element: eight
pull-up slices, eight pull-down, the active Miller clamp and the selectable
off rail. Generated by `scripts/kicad_driver_sheet.py`, which parses the
model file — so if a slice is added or `runit` changes, the drawing follows.

Until this existed, the only picture of the driver was a block diagram with
"8 × pull-up slice" written in a box. A box saying "8 slices" is a claim;
this is the circuit.

**How a slice works.** Each is a switch in series with a resistor, and the
resistor carries the thermometer code:

```
Rpu3 nu3 out {runit + (npu>=3 ? 0 : 1e9)}
```

Ask for three or more slices and `Rpu3` is `runit` — 8 Ω, in circuit. Ask
for fewer and it becomes 1 GΩ, which is that slice switched out. Drive
strength is how many of the eight parallel 8 Ω paths are live: 8 Ω at
`npu=1`, down to 1 Ω at `npu=8`.

The switches are voltage-controlled (`.model SWP`, Ron 0.01, Roff 1e9) — a
behavioural stand-in for the real output transistors. The sheet says so.

## The draw.io file

`gan_driver.drawio` is the same two circuits in an **editable** file. Open it
at [app.diagrams.net](https://app.diagrams.net) — File → Open From → Device.
Two pages: power stage, segmented driver. It uses draw.io's own electrical
shape library, so the symbols are standard rather than rectangles pretending
to be components.

This one exists for a specific reason: every other figure here is something
you can only look at. This one you can drag, retype and export. If anyone
asks whether the diagram is yours, opening it and changing something settles
it immediately.

Regenerate with `python3 scripts/drawio_circuit.py`. Values come from
`sim/buck.cir` and `models/segdrv.lib`, the same sources the KiCad sheets
read, so all three agree by construction rather than by someone remembering
to update them.

**Not verified visually here** — there is no draw.io CLI in this environment,
so the file is generated and its XML validated, but the layout has not been
rendered. Open it and check.
